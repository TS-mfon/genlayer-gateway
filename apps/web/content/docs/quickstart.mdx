# Quick start

## Prerequisites

- Node.js 22 or newer.
- Foundry.
- A MongoDB Atlas database.
- A Base Sepolia RPC endpoint.
- A funded Base Sepolia deployment wallet.
- A configured GenLayer testnet account for integration testing.

## Install

```bash
npm install
cp .env.example .env.local
npm run check
```

## Start the web product

```bash
npm run dev
```

The dashboard is available at `http://localhost:3000`. The health endpoint is `/api/v1/health`.

## Test contracts

```bash
npm run test:contracts
npm run test:genlayer:lint
```

Official GenLayer testnet tests are opt-in because they consume network resources:

```bash
RUN_GENLAYER_TESTNET_TESTS=1 gltest genlayer/tests/integration -v -s --network testnet_bradbury
```

## Safe deployment order

1. Deploy and configure the verified transport adapter.
2. Deploy `GatewayRouter` with the adapter address.
3. Bind the adapter to the router and verified GenLayer remote.
4. Deploy `AgentEscrow` with the router address.
5. Deploy the GenLayer adjudicator with the authorized transport submitter.
6. Perform a zero-economic-value round trip.
7. Run the 20-job official-testnet gate.
8. Configure Vercel and GitHub reconciliation only after the contracts pass.

## Which contract receives the request?

For the live MVP, Gateway operates one reviewed destination: `GatewayAdjudicator` on GenLayer Bradbury. Your Base application calls the origin-side `AgentEscrow` demo or `GatewayRouter`; it does not call GenVM directly. The relay reads the authenticated message, submits the typed `adjudicate` call to the configured Intelligent Contract, waits for a finalized result, and returns the result through the configured result receiver.

For custom Intelligent Contracts, use the route-aware V2 path. `GatewayRouteRegistry` stores the exact destination contract, method selector, argument schema, and result schema. `GatewayRouterV2.requestRoute` commits those values and the argument hash into the request ID before the transport message is sent. The route remains unavailable until a destination-specific adapter has been reviewed and tested.

The important boundary is:

```text
your application → origin Gateway contract → transport → reviewed GenLayer route
→ finalized Intelligent Contract result → authenticated callback → your application
```

Do not pass an arbitrary GenLayer address or method from a browser and treat it as trusted. A custom route is either approved and typed by Gateway or operated by your own adapter under the self-hosted security model.

## Minimal route-aware Solidity integration

The following is an integration shape for the V2 route-aware contract. Replace the route ID, typed argument encoding, callback, nonce, and expiry with values from the reviewed route package:

```solidity
bytes32 routeId = keccak256(bytes("gateway-adjudicator"));
bytes memory arguments = abi.encode(question, policy, evidenceUri);
(bytes32 requestId, bytes32 messageId) = gatewayRouter.requestRoute{value: 0.001 ether}(
    routeId,
    arguments,
    callback,
    nextNonce,
    expiry
);
```

The callback must authenticate the deployed Gateway receiver, bind the returned route ID to the request, reject replayed request IDs, and treat `UNDETERMINED` as a recoverable state. The read-only observatory at `/explorer` lets you inspect the resulting lifecycle without becoming a transaction sender.

## Inspect through the browser

Open `/explorer` to search and inspect recorded requests. The observatory does not connect a wallet or submit a transaction. Use `/docs/integration` for the application-side signing and callback flow, and `/evidence` for the published testnet deployment and phase-gate records.
