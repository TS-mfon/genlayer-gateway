# Developer observatory guide

The public website is intentionally read-only. It is designed for developers, reviewers, and hackathon judges who need to understand and inspect Gateway without connecting a wallet.

## Supported surfaces

- `/` — architecture, integration explanation, and evidence summary.
- `/explorer` — searchable request index with bounded polling for active requests.
- `/explorer` — also exposes the reviewed route catalogue: destination contract, method, schemas, executor readiness, and trust model.
- `/explorer/:requestId` — lifecycle, commitments, direct GenLayer read, and source comparison.
- `/evidence` — published deployment and phase-gate record.
- `/docs/*` — protocol and integration documentation.

There are no supported browser actions for creating escrow, submitting evidence, dispatching requests, or settling funds. Those actions belong to an integrating application or an operator-controlled relay.

The website is not a local job-management workspace. It does not persist browser-created jobs, claim work, or simulate settlement. This is intentional: a local browser store must never be confused with the origin-chain request registry or a finalized GenLayer result.

## Reading a request

Start at `/explorer` and search by the request ID, Base transaction hash, GenLayer transaction hash, LayerZero message ID, or evidence URL. Open a result to inspect the lifecycle. The page labels indexed values separately from the direct GenLayer read and displays a warning when they are unavailable or inconsistent.

The explorer stops polling terminal requests. Pending requests refresh automatically, but polling is best-effort and must not be used as a settlement authority.

## Source-of-truth boundary

MongoDB-backed lifecycle data is an operational projection. The direct result read is the canonical destination check for the active route. An origin application must still verify its own receipt, route binding, result receiver authorization, commitments, callback, and trust policy before applying an economic consequence.

## Evidence

The `/evidence` page renders the published deployment artifact and links to the smoke request, deployment transaction, and GenLayer transaction. It records the 20-job gate as `19/20` correct settlements and explains why the one no-result outlier remained fail-closed.

Use the [Explorer guide](/docs/explorer) for source labels and mismatch handling, and the [Integration guide](/docs/integration) for the programmatic developer workflow.
